# ZDS AI Convention

The ZDS Team's shared configuration for Claude Code, Codex CLI, Gemini CLI, and JetBrains Junie. Clone once, run the install script, and every team member's AI tools behave consistently: same branch names, same commit format, same MR structure, same skills.

---

## Integrate Guide: [ZDS AI Convention](https://docs.zalo.services/x/ZpW2D)

## Tool Compatibility

| AI Tool | `AGENTS.md` | Skills (`~/.agents/skills/`) | Sub Agents (`~/.agents/agents/`) |
|---|:---:|:----------------------------:|:--------------------------------:|
| **Claude Code** | ✅ |              ✅               |                ✅                 |
| **Codex CLI** (OpenAI) | ✅ |              ✅               |                ✅                 |
| **Gemini CLI** | ✅ |              ✅               |                ✅                 |
| **JetBrains Junie** | ✅ |              ✅               |                ✅                 |
| **GitHub Copilot** | ✅ |              ❌               |                ❌                 |

> Claude Code, Codex CLI, Gemini CLI, and Junie are installed against the same `~/.agents/` source of truth. `install.sh` wires `~/.claude/`, `~/.codex/`, `~/.gemini/`, and `~/.junie/` to that store, then writes `zds-*-codex` aliases so Codex can load ZDS skills with `--instructions`.

## Prerequisites

- At least one supported AI tool installed: Claude Code (`claude --version`), Codex CLI (`codex --version`), Gemini CLI (`gemini --version`), or Junie
- `GITLAB_TOKEN` set in shell profile (`[ -n "$GITLAB_TOKEN" ] && echo set`)
- VPN connected (required for `zalogit2.zing.vn` and `jira.zalo.services`)

## How It Works

The installer uses a **central `~/.agents/` store** with symlinks from each supported AI tool directory:

```
~/.agents/
├── skills/
│   ├── zds-make-mr/SKILL.md
│   ├── zds-review-mr/SKILL.md
│   └── ...                        ← copied from this repo
├── scripts/
│   ├── zds-gitlab-api             ← reads GITLAB_TOKEN internally
│   └── zds-jira-api               ← reads ~/.jira_cookie internally
└── agents/
    └── zds-git-branch-manager.md  ← copied from this repo

~/.claude/
├── skills  →  ~/.agents/skills    ← symlink
└── agents  →  ~/.agents/agents    ← symlink

~/.codex/
├── skills  →  ~/.agents/skills    ← symlink
└── agents  →  ~/.agents/agents    ← symlink

~/.gemini/
├── skills  →  ~/.agents/skills    ← symlink
└── agents  →  ~/.agents/agents    ← symlink

~/.junie/
├── skills  →  ~/.agents/skills    ← symlink
└── agents  →  ~/.agents/agents    ← symlink
```

**Why this layout:**
- `~/.agents/` is the single source of truth for all AI skills and agents
- `~/.claude/`, `~/.codex/`, `~/.gemini/`, and `~/.junie/` read from it via symlinks — no duplicate files
- Future AI tools can also point their skill directories at `~/.agents/` without copying
- Codex CLI users get `zds-*-codex` aliases in `~/.zshrc` pointing to the same files

**Manual setup (if you prefer not to run the script):**

```bash
# 1. Create the central store
mkdir -p ~/.agents/skills ~/.agents/agents ~/.agents/scripts

# 2. Copy skills from this repo
cp -r ~/zds-convention/skills/zds-*/ ~/.agents/skills/

# 3. Copy helper scripts from this repo
cp ~/zds-convention/scripts/zds-* ~/.agents/scripts/
chmod +x ~/.agents/scripts/zds-*

# 4. Copy agents from this repo
cp ~/zds-convention/agents/zds-*.md ~/.agents/agents/

# 5. Symlink tool directories to ~/.agents/
mkdir -p ~/.claude ~/.codex ~/.gemini ~/.junie
ln -s ~/.agents/skills ~/.claude/skills
ln -s ~/.agents/agents ~/.claude/agents
ln -s ~/.agents/skills ~/.codex/skills
ln -s ~/.agents/agents ~/.codex/agents
ln -s ~/.agents/skills ~/.gemini/skills
ln -s ~/.agents/agents ~/.gemini/agents
ln -s ~/.agents/skills ~/.junie/skills
ln -s ~/.agents/agents ~/.junie/agents
```

**Updating a skill after `git pull`:**

```bash
git pull
bash setup/install.sh   # re-copies to ~/.agents/ — symlinks stay in place
```

## Quick Reference

| Scenario | Use | Invocation |
|---|---|---|
| Create a branch only (no commit, no push) | `zds-create-branch` | `"create branch ZMBDTS-99 add user auth"` |
| Create branch + commit + push (no MR) | `zds-push-branch` | `"ZMBDTS-99 add user auth commit push"` |
| Branch + commit + push + MR in one shot | `zds-git-branch-manager` | `"ZMBDTS-99 update auth mr"` |
| Commit only (no branch change) | AI tool directly | `"commit my changes"` |
| Create a ZDS-standard MR | `zds-make-mr` | `"make mr"` |
| Review a GitLab MR + Jira cross-check | `zds-review-mr` | Paste MR URL |
| Look up a Jira ticket | `zds-jira-summary` | `"ZMBDTS-1524"` |
| Implement a Jira ticket | `zds-jira-ticket-implement` | `"implement ZMBDTS-1633"` |
| Refresh Jira cookie | `zds-update-jira-cookie` | `"update jira cookie"` |
| Sprint dashboard | `zds-sprint-review` | `"/zds-sprint-review"` |
| Migrate Conda env to micromamba | `zds-migrate-to-mamba` | `"migrate environment.yml to mamba"` |
| Update README + AGENTS.md | `zds-readme-updater` | `"update README"` |
| Document a function/class | `zds-generate-doc` | `"document MyClass.method"` |
| Publish a Markdown doc to Outline (zdocs) — create child, or update your own doc; needs zdoc link | `zds-outline-doc` | `"publish to zdocs <zdoc link>"` |
| Build task environment files from Airflow DAG | `zds-dag-env-builder` | `"build environment for path/to/dag.py"` |
| Compact context | Built-in | `"/compact"` |

## Updating the Convention

To propose a change:

1. Create a branch: `fts/convention-<topic>`
2. Edit the relevant file(s)
3. Open an MR — team lead reviews before merging
4. After merge: `git pull && bash setup/install.sh`

## Troubleshooting

**`GITLAB_TOKEN not set`**
```bash
# Export the token in your local shell profile. Do not paste token values in chat.
export GITLAB_TOKEN="..."
```

**`~/.jira_cookie` expired**
```
1. Open https://jira.zalo.services in browser (must be logged in)
2. F12 → Network → Reload → click "myself" → Request Headers
3. Copy the browser request cookie header value
4. In your terminal, write it to ~/.jira_cookie and chmod 600 the file.
```

**ZDS helper scripts missing**
```bash
bash ~/zds-convention/setup/install.sh
```

**Skill not recognized**
```bash
bash ~/zds-convention/setup/install.sh
```
